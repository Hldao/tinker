# Tinker 文风约束

替这个用户写 update / commit / 文档 / 产品文案时遵守：

- **纯中文**，不中英混杂。技术黑话翻成中文（写"一次性 token"不写"one-time token"）
- **避免斜体**（italic），用户会专门清理，别新增
- **避免 AI 标点堆**：不堆中点（`·`）、不堆破折号（`——`），用普通话口语化标点
- **工艺人日志气质**：不像 PM 周报，不像私人日记，像坐在工作台前边修边聊
- **拒绝商业黑话 / 管理咨询黑话**：`生态` `赋能` `抓手` `闭环` `底层逻辑` `颗粒度` `对齐` `复盘` 这些用户从不用，你也别用
- **用"我"不用"我们"**，用"人"不用"用户"
- **高频开头词**：`今天 / 今晚 / 凌晨 / 早上`，90% 的 update 这么起手
- **结尾留 takeaway**（下一步 / 学到了什么），不客套（`谢谢阅读` `欢迎反馈` 从不出现）
- **技术名词全小写**：`sqlite` `json` `https` `api`，不 ALL_CAPS
- **不编造情绪**（"咯噔""卡得厉害"），不下产品定论（"真正价值是 X"）
- **实事求是**：只写 git history 能找到的，不硬编
- **挑一个具体转向讲清楚 > 全部罗列**。150-280 字为宜

## voice fingerprint 的坑

`.tinker/voice-fingerprint.md` 是从过去样本自动生成的作者画像，起草前可以读它对齐语气。**但它会滞后于作者真实风格，甚至跟上面的明确规则冲突。**

踩过坑：旧画像说"中点是招牌，用得极高"，直接跟"别堆中点"打架，导致起草时堆了一堆被用户抓。**冲突时一律以上面的明确规则为准，别照画像。** 画像该定期用 `tinker voice analyze` 重新生成跟上真实风格。

## 产品立场（改 webapp / 写产品文案时）

反算法 / 反 trending / 反数据游戏。任何"加点赞 / 加排行 / 加推荐 / 加热度排序"的提议都先问是不是符合产品哲学。

可以加：真实复用反馈（接走、用了方法）、真实仪式（完工、卡住）。
不能加：浏览量、关注数、热度排序、stars。
